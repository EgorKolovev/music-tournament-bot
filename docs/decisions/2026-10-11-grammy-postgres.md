# Переход на grammY и PostgreSQL

11 октября 2026 года. Пакеты установлены, поэтому временные замены из [решений по боту](2026-10-08-telegram-bot.md#без-внешних-пакетов) убраны: бот работает на стеке из [архитектуры](../architecture.md), раздел 8. Игровые правила, сессии и оркестратор не менялись.

## grammY вместо своего клиента

- Вызовы Bot API — через `api.raw` grammY, с типами параметров и ответов. Свой клиент на `fetch` удалён.
- Long polling — `bot.start()`: grammY сам снимает webhook, повторяет `getUpdates` при сбоях сети и останавливается на 401 и 409. Офсет больше не берётся из inbox: Telegram отдаёт неподтверждённые updates, повторы отсеивает inbox в базе.
- Повторы отправки (429 с `retry_after`, 5xx, сеть) и правка на месте остались своими (`src/telegram/apiErrors.ts`): плагин auto-retry не ставили, логика уже покрыта тестами.
- Тесты подменяют Bot API transformer'ом grammY: настоящий `Api`, но без сети. Ответ `ok: false` grammY сам превращает в `GrammyError`, так что проверяется его настоящий путь ошибок.

## PostgreSQL вместо SQLite

- Те же таблицы и та же транзакция на событие (`src/storage/store.ts`). Методы хранилища стали асинхронными, поэтому `Runtime` создаётся через `Runtime.create`.
- JSON журнала и снимков хранится текстом, а не jsonb: jsonb переставляет ключи, а от порядка ключей зависит повтор журнала.
- Задачу аудио worker берёт через `FOR UPDATE SKIP LOCKED` — второй worker не возьмёт ту же.
- Проверка повтора update теперь ждёт ответа базы. Чтобы файлы пачки и нажатия не обгоняли друг друга, updates принимаются строго по очереди поступления — это проверяет отдельный тест.
- Если база недоступна в момент события, состояние не меняется, а на нажатие приходит «Ошибка, попробуйте ещё раз». Раньше SQLite в том же процессе так не отказывал.

## Тесты на PGlite

Тесты не должны требовать запущенного сервера PostgreSQL. Тесты хранилища и `Runtime` идут на PGlite — это PostgreSQL, собранный в WASM и запущенный в процессе тестов. Это dev-зависимость, в образ бота она не попадает. Перезапуск бота в тестах — новый `Store` над той же базой PGlite.

## Запуск и копии

- Docker Compose: сервисы `db` (postgres:17, том `pgdata`), `bot` и `backup`. Бот ждёт готовности базы.
- Копии теперь делает не бот, а сервис `backup`: `pg_dump` раз в `BACKUP_MINUTES` в `./backups` на хосте, хранятся последние 48. Целевой RPO — те же 5 минут из architecture.md, раздел 11.
- Для `npm run bot` без Docker нужен свой PostgreSQL и `DATABASE_URL`.
- Данные пробных запусков на SQLite не переносятся: боевого турнира на них не было.
