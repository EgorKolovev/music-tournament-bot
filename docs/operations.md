# Запуск бота

Как поднять бота локально и на сервере, провести пробный турнир и не потерять данные. Решения, стоящие за этим, — в [решениях по Telegram-боту](decisions/2026-10-08-telegram-bot.md).

## Подготовка

1. Создать в @BotFather два бота: тестовый для разработки и боевой. Токены не смешивать.
2. Узнать Telegram ID организатора и админов, например через @userinfobot.
3. Служебный чат для игровых версий аудио: подойдёт личный чат организатора с ботом (его ID) или закрытый канал, где бот — админ. Каждая перенарезка при подборе начала — новое аудио в этом чате, поэтому для турнира лучше канал.
4. Скопировать `.env.example` в `.env` и заполнить. Параметры турнира из `.env` — это настройки первого турнира при первом запуске; потом их меняет организатор в панели, а `.env` на них уже не влияет.

## Локально

Нужен Node.js 24, PostgreSQL и, для обработки аудио, ffmpeg. Адрес базы — `DATABASE_URL` в `.env`, по умолчанию `postgres://localhost:5432/tournament`; таблицы бот создаёт сам при первом запуске.

```bash
npm run bot
```

Копии и сброс — командами, база берётся из `DATABASE_URL`. Новый турнир для этого не нужен — он создаётся в боте (см. «Несколько турниров» ниже).

```bash
npm run db:backup                 # копия всех турниров в backups/tournament-<время>.json
npm run db:reset                  # стереть все турниры; следующий npm run bot начнёт новый с параметрами из .env
npm run db:restore                # вернуть последнюю копию из backups/
npm run db:restore -- backups/tournament-20261012-153000.json   # или конкретную
```

`reset` и `restore` показывают, что и где заменяют, спрашивают подтверждение (без вопроса — `-- --yes`) и перед заменой сами сохраняют текущий турнир в копию: случайный сброс откатывается `npm run db:restore`. Пока бот запущен, они откажутся; копию можно снять и на ходу. Локальные копии — JSON, их не нужно путать с копиями `pg_dump` из Docker Compose; в git папка `backups/` не попадает — в копиях ID и имена участников.

## На сервере

Docker Compose, три контейнера: `bot` (бот, worker аудио и ffmpeg), `db` (PostgreSQL на томе `pgdata`) и `backup` (копии базы). В `.env` нужен `POSTGRES_PASSWORD` — адрес базы для бота compose собирает сам.

```bash
docker compose up -d --build
docker compose logs -f bot
```

Новый турнир создаётся в боте. Стереть всё и начать с параметров из `.env`: `docker compose down -v` удаляет том с базой, затем `up` заново. Копии в `./backups` при этом остаются.

Входящие порты не нужны: long polling сам обращается к Telegram. Два экземпляра с одним токеном запускать нельзя — второй остановится с ошибкой 409.

Перенос между машинами: остановить бот, взять свежую копию из `./backups`, на новой машине восстановить её (см. ниже) и запустить.

## Пробный турнир

На четырёх аккаунтах удобно поставить `FINALISTS=2`, `MAX_SUBMISSIONS=10`, `FINAL_POOL_TARGET=20` и `AUDIO_MODE=skip`. Без `FINAL_POOL_TARGET` финальный пул рассчитан на 120 песен, и при 40 присланных все уйдут в финал — отбору нечего играть. Организатор может играть сам. Песни у всех разные: одинаковые склеиваются в одну, а игроку не выдаются песни, которые он прислал.

1. Организатор пишет боту `/start` — приходит панель админа со ссылкой-приглашением. Админы из `ADMIN_IDS` получают свою панель так же.
2. Участники открывают ссылку, выбирают имя, принимают правила и пересылают песни пачкой.
3. В панели, раздел «🎵 Сбор», организатор закрывает сбор и решает по недобравшим; на главном экране — «К жеребьёвке», в разделе «🗺 Сетка» — «Провести жеребьёвку».
4. Игроки в карточке пары выбирают судью; судья соглашается, второй игрок подтверждает. Судье приходит панель матча.
5. Когда отбор сыгран — «К финалу». Организатор отправляет ссылку судьи финала из панели, затем «Открыть финал»; пары на сцену — в разделе «🏆 Финал».
6. После финала — «Завершить турнир».

Что проверить на репетиции:

- правки панели судьи на месте, toast на нажатия, двойной клик по кнопке;
- пересылку 10 файлов из музыкального бота и список, который переезжает вниз;
- начало фрагмента: «⏱ Начало» текстом и «🎲 Случайно», «🎧 Послушать», сдвиги под фрагментом — с `AUDIO_MODE=ffmpeg` приходит перенарезанный фрагмент;
- обезличенный фрагмент у судьи: в плеере «Трек N · Музыкальный турнир», без обложки;
- перезапуск процесса посреди трека: счёт и панель на месте (`docker compose restart bot`);
- `/matches` у участника: кто играет, кто ждёт, что сыграно; меню команд в Telegram;
- `/status` у игрока, судьи и организатора: свой матч и его шаг, судейство, сводка;
- панель админа: разделы на каждом этапе, спор из уведомления «Открыть в панели», техническая победа в карточке матча, снятие в карточке участника — снятый проигрывает и текущий матч, и следующую пару;
- ники в «Участниках» и кнопка «Написать в Telegram»; своя панель у админа из `ADMIN_IDS` по `/panel`;
- «🎁 Только пришлю песни» при регистрации и `/leave` на сборе и на отборе: песни остаются, матч уходит сопернику;
- `/name` из меню и с именем: новое имя сразу у соперника в карточке пары и у судьи в панели матча; `/style` и `/name` видны в меню команд;
- удалить переписку с ботом и нажать «Старт»: на сборе приходят заново вводное и список песен, на отборе — список, карточка пары и панель матча;
- доступность Telegram из фактических сетей игроков и с машины, где крутится бот;
- «⚙️ Настройки»: смена значения на сборе, замок после закрытия сбора, жеребьёвки и первого матча; новый турнир и возвращение в прежний;
- «📦 Прислать бэкап» в «🗂 Все турниры»: приходит ZIP, `db:restore` поднимает из него пустую базу;
- «✉️ Рассылка» в панели: группы на каждом этапе, предпросмотр, сообщение приходит только выбранным.

## Несколько турниров

Пробный турнир не требует ни нового бота, ни сброса базы. Организатор в панели на главном экране нажимает «🗂 Все турниры» → «➕ Новый турнир», присылает название и подтверждает. Настройки берутся у текущего турнира, их можно поменять в «⚙️ Настройках» нового. Участники регистрируются заново — по новой ссылке-приглашению из панели.

Активен один турнир. Прежний встаёт на паузу: его кнопки, ссылка-приглашение и сообщения его участников получают ответ «на паузе», напоминаний о сроках нет. Вернуться — в «🗂 Все турниры», карточка турнира, «▶️ Перейти в этот турнир». Сроки кругов за время паузы не останавливаются: после возвращения их можно сдвинуть в «Сетке». Турниры не удаляются; `db:reset` стирает все разом.

## Резервные копии

Сервис `backup` раз в `BACKUP_MINUTES` минут делает `pg_dump` в каталог `./backups` рядом с `compose.yaml` и хранит последние 48 копий. Копии лежат на той же машине — их нужно регулярно забирать на другую.

Восстановление в Docker Compose:

```bash
docker compose stop bot
docker compose exec -T db pg_restore -U tournament -d tournament --clean --if-exists < backups/tournament-<время>.dump
docker compose start bot
```

Сообщения, не отправленные до сбоя, бот дошлёт сам.

## Бэкап от бота

Где сервиса `backup` нет — например, на Railway без платного тарифа, — бэкап присылает сам бот. Кнопки — у организатора в панели, «🗂 Все турниры», а не в настройках турнира: в бэкапе вся база, все турниры разом.

- «📦 Прислать бэкап» — сразу, например перед деплоем: ZIP в личку, то же, что `npm run db:backup`.
- «⏰ Присылать в 12:00» — каждый день в 12:00 по Москве. Если бот в 12:00 не работал, бэкап придёт после запуска в тот же день. Если с прошлого бэкапа ничего не изменилось, в этот день файла нет. По умолчанию выключено; выключить — там же («🔕 Не присылать в 12:00») или кнопкой «🔕 Больше не присылать» под бэкапом.

В копии ID, имена и ники участников, поэтому она приходит только организатору (`ORGANIZER_ID`). Песни в ней — ссылки Telegram, без самих mp3, и работают они только у того же бота: копия, восстановленная в бота с другим токеном, вернёт турнир и участников, а песни придётся прислать заново. Сами mp3 файлами — в финальном архиве.

Восстановление: остановить бота, положить файл в `backups/` и указать базу, куда восстанавливать. Для базы на Railway это публичный адрес — `DATABASE_PUBLIC_URL` у сервиса Postgres; внутренний `DATABASE_URL` с другой машины недоступен.

```bash
DATABASE_URL='postgresql://…' npm run db:restore -- backups/tournament-20261015-120000.zip
```

`db:restore` понимает и ZIP от бота, и JSON от `db:backup`; без имени файла берёт самую свежую копию из `backups/`. Потом запустить бота — неотправленные сообщения он дошлёт сам. Если архив вырастет больше лимита Telegram (50 МБ), вместо файла придёт сообщение — тогда копию снимает `npm run db:backup` с тем же `DATABASE_URL`.
