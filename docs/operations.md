# Запуск бота

Как поднять бота локально и на сервере, провести пробный турнир и не потерять данные. Решения, стоящие за этим, — в [решениях по Telegram-боту](decisions/2026-10-08-telegram-bot.md).

## Подготовка

1. Создать в @BotFather два бота: тестовый для разработки и боевой. Токены не смешивать.
2. Узнать Telegram ID организатора и админов, например через @userinfobot.
3. Служебный чат для игровых версий аудио: подойдёт личный чат организатора с ботом (его ID) или закрытый канал, где бот — админ.
4. Скопировать `.env.example` в `.env` и заполнить. Параметры турнира (название, код, число финалистов, seed) фиксируются в базе при первом запуске; менять их потом через `.env` бесполезно.

## Локально

Нужен Node.js 24, PostgreSQL и, для обработки аудио, ffmpeg. Адрес базы — `DATABASE_URL` в `.env`, по умолчанию `postgres://localhost:5432/tournament`; таблицы бот создаёт сам при первом запуске.

```bash
npm run bot
```

Новый турнир — пустая база: при остановленном боте пересоздать её (`dropdb tournament && createdb tournament`) или указать другую в `DATABASE_URL`.

## На сервере

Docker Compose, три контейнера: `bot` (бот, worker аудио и ffmpeg), `db` (PostgreSQL на томе `pgdata`) и `backup` (копии базы). В `.env` нужен `POSTGRES_PASSWORD` — адрес базы для бота compose собирает сам.

```bash
docker compose up -d --build
docker compose logs -f bot
```

Новый турнир: `docker compose down -v` удаляет том с базой, затем `up` заново. Копии в `./backups` при этом остаются.

Входящие порты не нужны: long polling сам обращается к Telegram. Два экземпляра с одним токеном запускать нельзя — второй остановится с ошибкой 409.

Перенос между машинами: остановить бот, взять свежую копию из `./backups`, на новой машине восстановить её (см. ниже) и запустить.

## Пробный турнир

На трёх-четырёх аккаунтах удобно поставить `FINALISTS=2`, `MAX_SUBMISSIONS=10` и `AUDIO_MODE=skip`.

1. Организатор пишет боту `/start` — приходят панель сбора и панель этапа со ссылкой-приглашением.
2. Участники открывают ссылку, выбирают имя, принимают правила и пересылают песни пачкой.
3. Организатор закрывает сбор, решает по недобравшим, нажимает «К жеребьёвке», затем «Провести жеребьёвку».
4. Игроки в карточке пары выбирают судью; судья соглашается, второй игрок подтверждает. Судье приходит панель матча.
5. Когда отбор сыгран — «К финалу». Организатор отправляет ссылку судьи финала из панели, затем «Открыть финал» и выводит пары на сцену.
6. После финала — «Завершить турнир».

Что проверить на репетиции:

- правки панели судьи на месте, toast на нажатия, двойной клик по кнопке;
- пересылку 10 файлов из музыкального бота и список, который переезжает вниз;
- обезличенный фрагмент у судьи: в плеере «Трек N · Музыкальный турнир», без обложки;
- перезапуск процесса посреди трека: счёт и панель на месте (`docker compose restart bot`);
- доступность Telegram из фактических сетей игроков и с машины, где крутится бот.

## Резервные копии

Сервис `backup` раз в `BACKUP_MINUTES` минут делает `pg_dump` в каталог `./backups` рядом с `compose.yaml` и хранит последние 48 копий. Копии лежат на той же машине — их нужно регулярно забирать на другую.

Восстановление в Docker Compose:

```bash
docker compose stop bot
docker compose exec -T db pg_restore -U tournament -d tournament --clean --if-exists < backups/tournament-<время>.dump
docker compose start bot
```

Сообщения, не отправленные до сбоя, бот дошлёт сам.
