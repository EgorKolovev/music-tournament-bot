# Музыкальный турнир

Telegram-бот, который ведёт турнир «угадай мелодию» целиком: собирает песни участников, проводит жеребьёвку, помогает парам найти судью, ведёт короткие отборочные матчи и очный финал.

**Статус:** бот готов к пробному турниру в Telegram: регистрация, сбор и обезличивание песен, жеребьёвка, судьи, отборочные матчи, споры, напоминания, финал и архив. Состояние хранится в PostgreSQL и переживает перезапуск. В настоящем Telegram ещё не проверялся — только тестами с подменой Bot API. Веб-симулятор остаётся инструментом для сценариев и презентаций. Числовые параметры регламента проверяются на пробных играх.

## Как проходит турнир

1. **Сбор треков.** Участники пересылают боту до 10 песен пачкой — например, из [@Music_to_you_bot](https://t.me/Music_to_you_bot); интеграции с ним нет. Названия бот берёт из тегов и имени файла, спрашивает только непонятное. Чужие дубли принимаются молча.
2. **Пулы.** После закрытия сбора бот сам делит песни на отбор и финал под число участников и показывает организатору достаточность. Недобравших без решения организатора в жеребьёвку не пускает.
3. **Жеребьёвка и пары.** Сетка на выбывание до 8 финалистов с проходами без игры. Карточка пары сразу показывает соперника и контакт; судью игроки выбирают из зарегистрированных. Сроки админ сдвигает в боте.
4. **Отборочный матч.** Короткий: 5 треков. Судья включает трек со своего телефона и отмечает исполнителя (0,9) и название (1,2) независимо. Ничья — по одному треку до разрыва.
5. **Финал.** Очный, через бота, судит не участник: 8 → 4 → 2 → 1 до 9,0. Песни идут из одной очереди с seed, песни пары на сцене пропускаются, прозвучавшее не повторяется. Офлайн-комплект с той же очередью — запасной план без интернета.

## Основные правила

- Игроку не выдаются песни, которые он прислал или слышал как судья; учёт знакомства не стирается при замене заявки.
- Финальные песни не используются в отборе; одна песня не бывает в двух пулах.
- Победа определяется после закрытия всего трека; порядок нажатия судейских кнопок не влияет на результат.
- Ничья не останавливает матч; остановка — только если кончились подходящие песни.
- Сложность песни не влияет на частоту её выдачи.

## Устройство

TypeScript, Node.js 24. Ядро бота транспортно-независимо: на вход получает действие пользователя (кнопка, текст, пересланные файлы), на выход отдаёт сообщения как данные — получатель, текст, кнопки, аудио или документ и slot для правки на месте. Оркестратор связывает этапы в один турнир, Telegram-адаптер (long polling) переводит сообщения в Bot API, веб-симулятор показывает их как чаты.

```
src/
  domain/      чистые правила: матч и регламенты, заявки и пулы, сетка, выбор песен
  bot/         сессии этапов: сбор, жеребьёвка, матч, финал — Incoming → Outgoing[]
  scenarios/   демо-данные, сценарии и их прогонщик (те же сценарии гоняются тестами)
  simulator/   веб-стенд на React и Vite
  tournament/  оркестратор турнира: этапы, регистрация, маршрутизация, споры, напоминания
  telegram/    адаптер Bot API: разбор updates, доставка, outbox, точка входа бота
  storage/     журнал событий, снимки, inbox, outbox, слоты, очередь аудио (PostgreSQL)
  worker/      обработка аудио: ffprobe, обезличенный фрагмент через ffmpeg, file_id
```

Бот — на grammY и PostgreSQL, плюс ffmpeg для аудио; тесты хранилища идут на PGlite, без сервера. Почему так — в [решениях по боту](docs/decisions/2026-10-08-telegram-bot.md) и [переходе на grammY и PostgreSQL](docs/decisions/2026-10-11-grammy-postgres.md).

## Быстрый старт

Как поднять бота у себя и пройти турнир на нескольких своих аккаунтах.

1. **Свой тестовый бот.** В [@BotFather](https://t.me/BotFather) — `/newbot`, он выдаст токен. Бот у каждого разработчика свой: два процесса с одним токеном не работают, второй остановится с ошибкой 409. Свой Telegram ID подскажет [@userinfobot](https://t.me/userinfobot).
2. **Настройки.** Скопировать `.env.example` в `.env` (`cp .env.example .env`) и заполнить `BOT_TOKEN` и `ORGANIZER_ID`. Для пробы на 2–4 аккаунтах поставить `FINALISTS=2` и `AUDIO_MODE=skip`: аудио не обрабатывается, ffmpeg не нужен, судья видит заглушку.

3. **База и запуск** — один из вариантов.

   **Docker** — Node.js и PostgreSQL ставить не нужно. В `.env` задать `POSTGRES_PASSWORD` из латинских букв и цифр.

   ```bash
   docker compose up -d --build
   docker compose logs -f bot
   ```

   **Без Docker, macOS** — нужен Node.js 24. `DATABASE_URL` из `.env.example` уже подходит: PostgreSQL из Homebrew пускает пользователя macOS без пароля и слушает только localhost.

   ```bash
   brew install postgresql@17
   brew services start postgresql@17
   $(brew --prefix postgresql@17)/bin/createdb tournament
   npm ci
   npm run bot
   ```

4. **Проверка.** В логе появятся `@имя_бота` и ссылка-приглашение. Написать боту `/start` — придут панели организатора. Ссылку отправить второму аккаунту, дальше — по [пробному турниру](docs/operations.md#пробный-турнир). Остановить — Ctrl+C или `docker compose down`.

Если не запускается:

- «Не задан …» — не заполнена строка в `.env`.
- «неверный BOT_TOKEN» — токен скопирован не целиком или отозван.
- «другой процесс уже читает updates» — с этим токеном уже запущен бот, свой или чужой.
- После запуска в логе тишина — бот не достучался до Telegram. Проверить сеть: `curl -m 10 https://api.telegram.org/` должен ответить сразу. Запускать там, где Telegram доступен.

`.env` в git не попадает. Токен никому не пересылать; если утёк — `/revoke` в @BotFather, старый перестанет работать сразу.

## Разработка

```bash
npm ci          # нужен Node.js 24
npm run dev     # стенд на http://localhost:5173
npm test        # правила, сценарии всех этапов и рендер стенда
npm run check   # проверка типов
npm run build   # сборка стенда в dist/
npm run bot     # Telegram-бот; нужен PostgreSQL, настройки — в .env (см. .env.example)
docker compose up -d --build   # бот на сервере
```

Как провести пробный турнир и делать резервные копии — в [запуске бота](docs/operations.md).

Стенд публикуется на GitHub Pages из `main` (`.github/workflows/pages.yml`). Pages один раз включается в Settings → Pages → Source: GitHub Actions. На стенде только вымышленные участники и метаданные песен, аудио нет.

Музыкальные файлы, пользовательские данные и секреты в репозиторий не входят.
