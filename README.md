# Музыкальный турнир

Telegram-бот, который ведёт турнир «угадай мелодию» целиком: собирает песни участников, проводит жеребьёвку, помогает парам найти судью, ведёт короткие отборочные матчи и очный финал.

**Статус:** готов демо-стенд — веб-симулятор бота со всеми этапами турнира по решениям от 8 октября. Игровая логика написана и покрыта тестами; Telegram-адаптер, хранение в PostgreSQL и обработка аудио ещё не подключены. Числовые параметры регламента проверяются на пробных играх.

## Как проходит турнир

1. **Сбор треков.** Участники пересылают боту до 10 песен пачкой — например, из [@Music_to_you_bot](https://t.me/Music_to_you_bot); интеграции с ним нет. Названия бот берёт из тегов и имени файла, спрашивает только непонятное. Чужие дубли принимаются молча.
2. **Пулы.** После закрытия сбора бот сам делит песни на отбор и финал под число участников и показывает организатору достаточность. Недобравших без решения организатора в жеребьёвку не пускает.
3. **Жеребьёвка и пары.** Сетка на выбывание до 8 финалистов с проходами без игры. Карточка пары сразу показывает соперника и контакт; судью игроки выбирают из зарегистрированных. Сроки админ сдвигает в боте.
4. **Отборочный матч.** Короткий: 5 треков. Судья включает трек со своего телефона и отмечает исполнителя (0,9) и название (1,2) независимо. Ничья — по одному треку до разрыва.
5. **Финал.** Очный, через бота, судит не участник: 8 → 4 → 2 → 1 до 9,0. Песни идут из одной очереди с seed, песни пары на сцене пропускаются, прозвучавшее не повторяется. Офлайн-комплект с той же очередью — запасной план без интернета.

## Основные правила

- Игроку не выдаются песни, которые он прислал или слышал как судья; учёт знакомства не стирается при замене заявки.
- Финальные песни не используются в отборе; одна песня не бывает в двух пулах.
- Победа определяется после закрытия всего трека; порядок нажатия судейских кнопок не влияет на результат.
- Ничья не останавливает матч; остановка — только если кончились подходящие песни.
- Сложность песни не влияет на частоту её выдачи.

## Устройство

TypeScript, Node.js 24. Ядро бота транспортно-независимо: на вход получает действие пользователя (кнопка, текст, пересланные файлы), на выход отдаёт сообщения как данные — получатель, текст, кнопки, аудио или документ и slot для правки на месте. Telegram-адаптер (grammY, long polling) будет переводить их в Bot API, веб-симулятор показывает как чаты.

```
src/
  domain/      чистые правила: матч и регламенты, заявки и пулы, сетка, выбор песен
  bot/         сессии этапов: сбор, жеребьёвка, матч, финал — Incoming → Outgoing[]
  scenarios/   демо-данные, сценарии и их прогонщик (те же сценарии гоняются тестами)
  simulator/   веб-стенд на React и Vite
```

Целевой прод-стек: grammY, PostgreSQL и Drizzle, очередь задач в PostgreSQL, FFmpeg для аудио, Docker Compose.

## Разработка

```bash
npm ci          # нужен Node.js 24
npm run dev     # стенд на http://localhost:5173
npm test        # правила, сценарии всех этапов и рендер стенда
npm run check   # проверка типов
npm run build   # сборка стенда в dist/
```

Стенд публикуется на GitHub Pages из `main` (`.github/workflows/pages.yml`). Pages один раз включается в Settings → Pages → Source: GitHub Actions. На стенде только вымышленные участники и метаданные песен, аудио нет.

Музыкальные файлы, пользовательские данные и секреты в репозиторий не входят.
