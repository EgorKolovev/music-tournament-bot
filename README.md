# Музыкальный турнир

Telegram-бот для очных музыкальных матчей между двумя игроками с выбранным ими судьёй и для подготовки автономного финала.

**Статус:** в репозитории находится архитектура решения. Код бота ещё не реализован. Числовые параметры регламента предложены для первого турнира и проверяются до его запуска.

Полная спецификация: **[Архитектура решения](docs/architecture.md)**.

## Как проходит турнир

1. Участники регистрируются и сами отправляют готовые аудиофайлы в основной и финальный пулы. Для подготовки файлов можно использовать [@Music_to_you_bot](https://t.me/Music_to_you_bot); интеграции с ним у турнирного бота нет.
2. Бот проверяет заявки и дубли, создаёт обезличенные игровые копии и формирует сетку.
3. Два игрока выбирают третьего человека судьёй. Только эта пара и судья слышат музыку своего матча.
4. Судья получает треки и отмечает исполнителя и название независимо. Бот сохраняет счёт, статистику и подтверждённые результаты.
5. После определения финалистов организатор скачивает аудиофайлы, плейлист, список игроков и отдельную таблицу ответов. Финал проводится без бота и интернета.

## Основные правила

- Игроку не выдаются его собственные песни, их дубли и треки, с которыми он уже познакомился в игре или в роли судьи.
- Повторы между независимыми парами разрешены. Внутри одного матча повторов нет.
- Финальные песни никогда не используются в отборе.
- Из общего офлайн-пакета финала исключаются песни всех финалистов.
- Победа определяется после закрытия всего трека; порядок нажатия судейских кнопок не влияет на результат.
- Сложность песни не влияет на частоту её выдачи.

## Предлагаемая архитектура

Модульное приложение на Python: **aiogram, PostgreSQL, SQLAlchemy, Alembic и FFmpeg**. Процесс бота обслуживает игровые действия, отдельный worker обрабатывает аудио и собирает экспорт. Очереди и журнал действий хранятся в PostgreSQL.

Для запуска предусмотрен Docker Compose: на одной VM в Yandex Cloud с закрытым Object Storage либо локально с файловым хранилищем. Бот получает события через long polling. Для отборочных интернет необходим; скачанный финальный комплект автономен.

## Что описано в спецификации

- Регистрация, загрузка файлов, проверка ответов и обезличивание аудио.
- Назначение судьи, судейская панель, подсчёт очков, отмены и споры.
- Сетка с проходами без игры и завершение отбора.
- Разделение пулов, учёт известных песен и проверка запаса.
- Формат финального экспорта и исключение собственных треков.
- Компоненты приложения, модель данных и транзакции.
- Развёртывание в РФ и локально, резервные копии, безопасность и статистика.
- Этапы реализации, критерии приёмки и технические источники.

Музыкальные файлы, пользовательские данные и секреты в репозиторий не входят.
